1. EXECUTIVE FINDING

The final application is an AI-driven marketing image generation system for product-based promotional content. It combines business context, product information, optional product imagery, a selected Philippine holiday or marketing event, campaign information, and creative preferences to produce a marketing image.

The primary output is an AI-generated marketing image that can be previewed, saved, downloaded, or regenerated. The application does not implement external content publishing, social account management, or automatic posting.

4. VERIFIED ROUTE WORKFLOW

The active routes include authentication/OAuth, onboarding, dashboard, profile/settings, products, events/calendar, campaigns, generator, designs, notifications, subscriptions, and OpenAI telemetry. The generation-specific routes are:

- GET `/generator` -> `GeneratorController::index`
- POST `/generator/preview` -> synchronous preview without a permanent Design record
- POST `/generator` -> validated generation and persistent Design creation
- GET `/designs` -> My Designs
- GET `/designs/{design}` -> design detail
- POST `/designs/{design}/regenerate` -> synchronous new variation and new Design
- GET `/designs/{design}/download` -> authorized binary download

No publishing, Graph API, external post, platform-token, webhook, or social-scheduling route exists.

5. AI MARKETING STUDIO INPUT AUDIT

Required by the main GeneratorRequest:
- Product name.
- Event ID.
- Marketing goal.

The preview endpoint separately validates product name, image prompt, and event ID; its validation/ownership parity is a remaining concern.

Optional inputs include product ID, campaign ID, price, product description, tagline, tagline mode, content style, brand tone, visual theme, render style, aspect ratio, image model, image quality, business-name inclusion/name, notes, scene/image prompt, and a JPG/JPEG/PNG/WebP reference image up to 5 MB.

The UI requires product name, image prompt, and event selection before initiating preview generation. A catalog product may supply the product image automatically. A custom uploaded reference may also be supplied.

6. VERIFIED AI PIPELINE

1. The Studio collects the creative form data.
2. The controller resolves the authenticated business and selected product/campaign/event context.
3. Uploaded references are stored under `generation-requests/`; catalog images are resolved from product storage paths.
4. `MarketingPromptBuilder` constructs a promotional advertisement brief.
5. `ReferenceImageAnalyzer` may call OpenAI Vision (`gpt-4o-mini`) to obtain supplemental observations.
6. `ModularPromptOrchestrator` adds root/output guardrails and ten ordered modules.
7. `OpenAIImageService` resolves the model and API canvas size.
8. A supported reference image is attached to `/v1/images/edits`.
9. Without a usable reference, or after an edit failure, `/v1/images/generations` is called.
10. Base64 or temporary URL response data is converted to binary.
11. The binary is stored at `designs/openai_{uuid}.png` on the public disk.
12. Preview returns image URL/path and metadata. Save creates a Design. Regeneration creates a GenerationRequest and a new Design.

Generation is synchronous. Frontend progress messages represent UX feedback, not separately measured backend phases.

7. PROMPT ORCHESTRATION AUDIT

The active `ModularPromptOrchestrator` uses a root commercial objective and anti-logo rule, ten ordered priority modules, and output/safety guardrails:

1. Primary product image and preservation.
2. User scene/visual direction.
3. Final marketing copy.
4. Campaign name/objective.
5. Event/Philippine holiday direction.
6. Industry/category art direction.
7. Business context and brand identity.
8. Render style.
9. Visual theme.
10. Responsive composition and invisible safe area.

The prompt tells the model to keep product identity primary, preserve enabled copy text, and keep environmental styling subordinate. It forbids invented logos, emblems, watermarks, badges, and brand marks.

8. PRODUCT IMAGE AUDIT

Catalog product uploads and Studio reference uploads are stored using Laravel's public disk. Main generation validation accepts JPG, JPEG, PNG, and WebP up to 5 MB. The actual stored binary is used in an image-edit request when the selected model supports image input. Vision metadata is supplemental and does not replace the binary.

Without a reference image, the model synthesizes a product and full commercial scene from the product and business prompt. With a reference image, the prompt asks the model to preserve recognizable identity, geometry, colors, labels, textures, and accessories while changing primarily the surrounding scene. This does not guarantee pixel identity. If image editing fails, text-to-image fallback may occur.

9. INDUSTRY AND EVENT AUDIT

`IndustryCategoryArtDirectionService` has dedicated branches for food/beverage, beauty/wellness, automotive, technology, retail/fashion, real estate, travel/hospitality, healthcare, fitness, professional services, and education, with a generic fallback. Each branch supplies environment, materials, lighting, props, commercial conventions, and exclusions.

`PhilippineHolidayService` creates repository-defined regular holidays, special non-working holidays, special working observances, Islamic holidays, commercial shopping dates, shifted dates, long-weekend metadata, and custom events. Events are global or user-scoped. The repository contains proclamation labels; independent government-source verification was not performed.

Recognized event names are translated by the orchestrator into mood, environment, lighting, decorative direction, spatial staging, and marketing intent. The event guides the image's atmosphere and promotional context; it does not automatically create or publish a campaign.

10. COPY, TAGLINE, LOGO, AND COMPOSITING AUDIT

- Product name, enabled business/shop name, price, and normalized tagline are sent as exact model instructions for visible commercial typography.
- `TaglineNormalizationService` trims whitespace, removes enclosing straight/smart quotes, removes repeated trailing dots/ellipses and dangling punctuation/connectors, preserves internal text and trailing `!`/`?`, and returns null when empty. It does not generate wording.
- Business-name typography is allowed; logo/emblem/watermark generation is explicitly prohibited.
- `ImageCompositorService` creates a manifest with canvas, safe margins, and exact content metadata. It does not load pixels, draw text, or create a final composited raster image.
- `MockupImageService` can generate an SVG fallback for tests/local operation and is not evidence of the production OpenAI compositor.

12. DATABASE AUDIT

- User has one Business and many Product, Event, Campaign, Design, GenerationRequest, and AppNotification records.
- Business has many Product, Campaign, and Design records.
- Event belongs to a User or is global, and has Campaign/Design associations. It has no final business_id relationship.
- Campaign may reference Product/Event and has Design associations.
- Design may reference Product/Event/Campaign and stores generated path and metadata.
- GenerationRequest records request context, prompt, reference path, and processing status.
- Product and Design use soft deletes.
- Foreign-key nulling/cascade behavior is defined in migrations.
