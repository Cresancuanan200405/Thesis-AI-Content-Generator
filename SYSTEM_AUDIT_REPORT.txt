1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
The "AI-Driven Marketing Content Generator" (MarketPilot / AI Marketing Automation) 
is a full-stack web application designed for micro, small, and medium enterprises (MSMEs), 
specifically targeting Philippine businesses. Its core function is allowing business 
owners to generate promotional marketing visual assets aligned with Philippine national 
and cultural holidays, localized marketing calendar events, product catalog items, 
and customizable branding preferences.

The application allows users to:
1. Define business profiles (industry, category, branding, tone, logo).
2. Maintain a catalog of products (name, description, price, category, product photography).
3. Browse a Philippine Holiday and Marketing Calendar with automated and custom events.
4. Launch an AI Visual Marketing Studio with 4 render styles, brand tones, visual themes, 
   aspect ratios, price tags, taglines, and image uploads.
5. Generate promotional graphics using OpenAI image models with Vision-assisted 
   visual analysis and store them in a persistent design portfolio.

Key Findings from Audit:
- [CONFIRMED FROM CODE] The system uses Laravel 12 / PHP 8.5 on the backend and React 19 / 
  Inertia.js v2/v3 / TypeScript / Tailwind CSS / Lucide icons on the frontend.
- [CONFIRMED FROM CODE] Database layer is SQLite (with MySQL/PostgreSQL compatibility via Eloquent).
- [CONFIRMED FROM CODE] AI Image generation is performed via direct HTTP POST requests to OpenAI 
  `https://api.openai.com/v1/images/generations` using models `chatgpt-image-latest` / `gpt-image-1` 
  / `dall-e-3`.
- [CONFIRMED FROM CODE] Reference/product image analysis is performed using OpenAI Vision 
  (`gpt-4o-mini` via `https://api.openai.com/v1/chat/completions`) in `ReferenceImageAnalyzer.php`.
- [CONFIRMED FROM CODE] Text rendering is generated entirely within the raster image by OpenAI's 
  image diffusion model (no separate canvas/SVG typography post-compositing is performed).

3. SYSTEM ARCHITECTURE
--------------------------------------------------------------------------------
The end-to-end architecture follows a unified pipeline:

[ USER INTERFACE (React / Inertia.js) ]
  ├── Studio Form State (Product, Price, Tagline, Style, Tone, Theme, Event, Aspect Ratio, Reference Image)
  └── Dispatches multipart/form-data POST via fetch() to `/generator/preview` or form submit to `/generator/store`
       ↓
[ ROUTING & CONTROLLER LAYER ]
  ├── `routes/web.php` -> `GeneratorController::generatePreview` / `GeneratorController::store`
  └── Form validation (`product_name` required, `image_prompt` nullable, uploaded files validated)
       ↓
[ STORAGE & ASSET MANAGEMENT ]
  ├── Uploaded Reference / Catalog Image stored in `storage/app/public/generation-requests/`
  └── Fallback to catalog product path (`storage/app/public/products/...`)
       ↓
[ AI ORCHESTRATION & PROMPT BUILDER ]
  ├── `MarketingPromptBuilder.php` -> Builds user content brief
  ├── `ReferenceImageAnalyzer.php` -> Calls OpenAI Vision (gpt-4o-mini) to extract structured JSON blueprint
  └── `OpenAIImageService.php` -> Assembles Product-First prompt (Product Truth + 5-Level Typography + Safe Margins)
       ↓
[ OPENAI IMAGE GENERATION API ]
  └── POST `https://api.openai.com/v1/images/generations` (model, prompt, size, n=1, quality)
       ↓
[ RESPONSE HANDLING & IMAGE PERSISTENCE ]
  ├── Downloads binary from temporary URL / base64 response
  ├── Saves final PNG to `storage/app/public/designs/openai_{uuid}.png`
  ├── Records entry in `designs` table with `generation_metadata`
  └── Returns JSON with `image_url` to React frontend for instant preview / download

HOW THE PRODUCT IMAGE IS CURRENTLY USED BY THE IMAGE GENERATION SYSTEM:
Current Implementation: [CONFIRMED FROM CODE - Combination of A, C, G]
1. When a user selects a product from the catalog or uploads a desktop photo, the file path 
   (`storage/app/public/...`) is passed to `OpenAIImageService.php` in the `$options['reference_image_path']`.
2. `ReferenceImageAnalyzer.php` reads the local image file, base64-encodes it, and sends it to 
   OpenAI Vision (`gpt-4o-mini`) via the Chat Completions API with multimodal image payload.
3. OpenAI Vision inspects the image and returns a structured JSON blueprint describing:
   - `product_identity`: Exact visual characteristics (container, layers, ingredients, toppings, etc.).
   - `product_physical_details`: Mandatory physical details to preserve.
   - `composition`, `layout`, `background`, `lighting`, `color_palette`, `typography`, `negative_space`.
4. `OpenAIImageService.php` converts this blueprint into an authoritative textual prompt directive:
   "AUTHORITATIVE PRODUCT FIDELITY (SOURCE OF TRUTH)..." and passes it to the OpenAI Image Generation endpoint.
5. The DALL-E / ChatGPT image model generates the raster output based on this detailed prompt.

7. IMPORTANT PRODUCT-PRESERVATION EVALUATION
--------------------------------------------------------------------------------
Evaluation of Current Behavior:
- The system extracts the physical features of the product via Vision and instructs the text-to-image 
  model to recreate the exact physical characteristics.
- LIMITATION OF TEXT-TO-IMAGE GENERATION: Because OpenAI's `images/generations` endpoint is a pure 
  text-to-image diffusion process rather than a pixel-compositing / inpainting pipeline, the image model 
  *synthesizes a new rendering* of the product described in the prompt rather than keeping the 
  exact original pixels of the uploaded photograph.
- If true pixel preservation (e.g. keeping the 100% exact photographed burger cutout with untouched 
  original pixels and only generating a background around it) is required, the architecture requires 
  a hybrid canvas compositing pipeline (e.g. background removal -> AI background generation -> 
  raster compositing) or OpenAI Inpainting / Image Edit API (`https://api.openai.com/v1/images/edits`).

17. IMAGE GENERATION API INTEGRATION
--------------------------------------------------------------------------------
[CONFIRMED FROM CODE]
File: `app/Services/OpenAIImageService.php`

Endpoint: `POST https://api.openai.com/v1/images/generations`
Headers:
  `Authorization: Bearer [REDACTED]`
  `Content-Type: application/json`
  `OpenAI-Organization: [REDACTED]` (if configured)

Payload Structure:
```json
{
  "model": "chatgpt-image-latest",
  "prompt": "[PRODUCT-FIRST PROMPT STRING - max 3900 chars]",
  "n": 1,
  "size": "1024x1024",
  "quality": "standard"
}
```

Response Handling:
- Checks HTTP status; if non-200, extracts error message and logs.
- Retrieves image from `b64_json` or downloads binary from temporary `url`.
- Generates unique filename `designs/openai_{uuid}.png`.
- Writes binary to Laravel `Storage::disk('public')->put($filename, $binary)`.
- Returns relative path for database storage and client rendering.

18. COMPLETE IMAGE GENERATION EXECUTION TRACE
--------------------------------------------------------------------------------
[CONFIRMED FROM CODE]

1. USER INTERACTION:
   - User navigates to `/generator` (or clicks "Generate AI Visuals" from Product Catalog / Event Calendar).
   - Form state populated (Product, Price, Event, Tagline, Style, Tone, Aspect Ratio, Reference Photo).
   - User clicks "Generate Visual Creative".

2. FRONTEND SUBMISSION:
   - `resources/js/pages/generator/index.tsx` constructs `FormData` with all fields and attached files.
   - Dispatches `POST /generator/preview` via `fetch()`.

3. BACKEND ROUTING & CONTROLLER:
   - `routes/web.php` routes to `GeneratorController::generatePreview`.
   - `GeneratorController` validates request payload.
   - Saves uploaded `reference_image` to `storage/app/public/generation-requests/`.

4. AI VISION ANALYSIS:
   - `ReferenceImageAnalyzer::analyze()` sends image to OpenAI Vision (`gpt-4o-mini`).
   - Returns structured JSON blueprint (Product Source of Truth + Layout + Lighting + Colors).

5. PROMPT SYNTHESIS:
   - `OpenAIImageService::buildCommercialPrompt()` builds Product-First prompt:
     [Product Truth] + [Visual Blueprint] + [5-Level Typography] + [20% Safe Margins].

6. API CALL TO OPENAI:
   - `OpenAIImageService::executeDallEImageGeneration()` calls `https://api.openai.com/v1/images/generations`.

7. IMAGE PERSISTENCE:
   - Decodes response binary and writes to `storage/app/public/designs/openai_{uuid}.png`.

8. METADATA RECORD & CLIENT DISPLAY:
   - Controller returns JSON containing `image_url`, `prompt`, `reference_blueprint`, and design params.
   - Frontend sets `generationState = 'ready'` and renders the interactive preview canvas with Download, Save to Portfolio, and Export options.

21. SAMPLE OUTPUT ANALYSIS (Flame-Grilled Ribeye Steak Case Study)
--------------------------------------------------------------------------------
Audit Analysis of Previous Output Discrepancies:
1. Product Identity Drift:
   - Root Cause: In earlier builds, the system passed product information as pure text ("Flame-Grilled Ribeye Steak") without extracting or enforcing visual characteristics from the uploaded photo, causing the AI model to invent its own interpretation.
2. Hardcoded Dark Pedestal Overrides:
   - Root Cause: Earlier versions hardcoded "sleek dark pedestal with flowing metallic ribbons and gold double-ring seal" in `OpenAIImageService.php`, which overrode all user-selected styles.
3. Typography Cropping:
   - Root Cause: Text positioned too close to canvas boundaries without mandatory 20% safe margin padding.


--------------------------------------------------------------------------------
22. PROMPT ARCHITECTURE & POTENTIAL CONFLICTS
--------------------------------------------------------------------------------
Analysis of Potential Conflicts:
- Conflict Scenario 1 (Render Style vs. Background Theme):
  If user selects "Minimalist Graphic" (flat 2D vector style) but selects "Cozy Cafe Vibe" (3D realistic photography environment), the prompt previously sent contradictory directives.
- Conflict Scenario 2 (Dark Theme Overrides vs. Pastel Food Photography):
  Hardcoded lighting strings previously overrode organic food styling.
- Solution Implemented:
  The prompt architecture now strictly enforces:
  `ART DIRECTION PRINCIPLE: PRODUCT FIRST -> MARKETING MESSAGE SECOND -> DECORATIVE ELEMENTS THIRD`
  with explicit hierarchy layers and safe margins.

23. PRIORITIZED PROBLEMS
--------------------------------------------------------------------------------
### CRITICAL
1. Text-to-Image Diffusion Re-synthesis vs. Pixel Preservation:
   - Pure text-to-image models re-render products based on descriptions rather than compositing the exact raw pixels of uploaded photography. For 100% pixel-accurate product preservation, a background-removal + canvas-compositing pipeline is required.

### HIGH
2. Logo Redrawing:
   - DALL-E redacts/re-renders logos as text emblems rather than preserving vector/PNG brand logos.

### MEDIUM
3. Typography Flexibility:
   - Diffusion-generated text cannot be edited after generation without regenerating the entire image.

### LOW
4. Resolution Customization:
   - Standard DALL-E sizes are capped at 1024x1024, 1792x1024, and 1024x1792.
